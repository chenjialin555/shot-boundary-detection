# 调参与标定 SOP

## 0. 为什么单镜头视频是分水岭

绝大多数分镜算法 demo 都在“有切点”的素材上测，看起来 F1 很高。
一上真实素材就崩，原因通常是**单镜头视频**：

- 一个 8 分钟的访谈、一个长镜头跟拍 → 期望输出是 `[]`（0 个切点）；
- 相对阈值却一定会切出 2~5 段；
- F1 在这种视频上**无定义**，所以这个缺陷在报告里完全看不见。

所以标定的第一原则：**数据集里必须有足够的单镜头负样本**，指标必须包含 FAR。

## 1. 数据集准备

推荐的最小规模：

| 类别 | 数量 | 要求 |
|---|---|---|
| 硬切 | 10+ 段 | 含快剪、相似场景切换 |
| 渐变 | 5+ 段 | 叠化、淡入淡出 |
| **单镜头** | **20+ 段** | 手持、甩镜、变焦、光照变化、黑场淡入淡出、长镜头跟拍 |

目录结构：

```
dataset/
  clip01.mp4
  clip01.json      {"cuts": [312, 900], "fps": 25, "duration_s": 60}
  ...
  single01.mp4
  single01.json    {"cuts": [], "fps": 30, "duration_s": 480}
```

或者一个 `labels.json`：

```json
{"clips": [{"video": "clip01.mp4", "cuts": [312, 900], "fps": 25}]}
```

## 2. 标定 `t_abs`

```bash
python -m sbd calibrate dataset/ --alpha 1e-4 -o calib.json
```

它做的事情：

1. 对所有样本算 `d[i]`；
2. **同镜头帧差**（切点 ±5 帧以外）→ 零分布 $H_0$；
3. **切点帧差**（切点 ±1 帧取最大）→ 备择分布 $H_1$；
4. 报告 $H_0$ 的 p99 / p99.9 / max、$H_1$ 的 min / p05 / p50、AUC；
5. 给出建议值：

$$
t_{\text{abs}} = \frac{Q_{1-\alpha}(H_0) + Q_{0.05}(H_1)}{2}
$$

**关键概念：$\alpha$ 是“每帧虚警率”，不是“每个视频”。**
若要求“每个视频至少误检一次”的概率 ≤ 5%，应使用**最大值统计量**：

$$
P\big(\max_{i \le n} d_i \le T \,\big|\, H_0\big) = 0.95
$$

否则 1 小时的视频（108000 帧）在 $\alpha=10^{-4}$ 下平均仍有 ~10 次误检。
`calibrate` 报告里的 `negative_clip_max` 就是给这个用的：**阈值至少要高于它**。

### 读标定结果的三种情况

| 现象 | 诊断 | 处理 |
|---|---|---|
| $Q_{0.05}(H_1) \gg Q_{0.999}(H_0)$ | 分离度好 | 直接用建议值 |
| 两者接近，AUC < 0.9 | 直方图区分力不足 | 换 HSV、增加 H 的 bin、加空间校验 |
| $Q_{0.05}(H_1) < Q_{0.999}(H_0)$ | 噪声尾部盖住了弱切点 | **单靠直方图无解**，必须加持续性检验/空间特征 |

## 3. 参数逐项说明

| 参数 | 默认 | 物理含义 | 调大的后果 | 调小的后果 |
|---|---|---|---|---|
| `t_abs` | 0.38 | 硬切的最小物理距离 | 漏检弱切 | 误检运动 |
| `k_mad` | 6.0 | 局部异常倍数 | 漏检 | 误检 |
| `window` | 25 | 局部统计半窗（帧） | 适应慢，跨镜头污染 | 阈值抖动 |
| `local_max_gap` | 3 | 峰值抑制半径 | 相邻两切合并 | 一个切点检两次 |
| `min_shot_len_s` | 0.5 | 最短镜头 | 漏掉快剪 | 闪白连切 |
| `persistence_k` | 8 | 持续性窗口 | 短镜头处理变差 | 置信度下降 |
| `t_persist` | 0.28 | 持续性下限 | 漏检 | 误检 |
| `persist_snr` | 2.0 | 跳跃/内部波动比 | 漏检 | 误检 |
| `flash_ratio` | 0.35 | 闪光判据 | 闪光漏杀 | 真闪切被误杀 |
| `gradual_total` | 0.35 | 渐变累积变化 | 漏检渐变 | 误检运动 |
| `gradual_coherence` | 0.60 | 渐变单向性 | 漏检 | 误检往返摇镜 |
| `gradual_post_quiet` | 0.60 | 结束静默比 | 漏检 | 误检持续运动 |

## 4. 调参顺序（很重要）

```
1. 固定其他默认，先标定 t_abs        → 把单镜头误检压到 0
2. 再看正样本召回，漏检多就降 k_mad    → 不要先动 t_abs
3. 闪光/甩镜仍误检 → 检查 persistence 是否开启, persist_snr 提到 2.5
4. 渐变漏检 → 降 gradual_total / coherence, 或单独上空间校验
5. 最后才动 bins（它会让 1~4 全部重来）
```

**换 `bins` 或 `space` 之后，`t_abs` 必须重新标定。**

## 5. 评估协议

```bash
python -m sbd eval dataset/ --tol 2 -o report.json
```

- **容差**：±2 帧（约 80ms）内算命中。硬切定位通常 ±1 帧，渐变起点本身模糊，建议 ±5。
- **分开统计**：硬切、渐变、单镜头负样本分别报，混在一起会掩盖问题。
- **主指标**：
  - 正样本：Precision / Recall / F1；
  - 负样本：FAR（次/分钟）、零误检片段占比；
  - 上线门槛建议：**FAR ≤ 0.1 次/分钟**，且零误检片段占比 ≥ 90%。

### 不要用 F1 的情况

当 `n_gt = 0`：`precision = 0`、`recall` 无定义、`F1` 无定义。
`metrics.evaluate` 会返回 `f1: null` 并置 `f1_defined: false`，
`aggregate` 会把负样本单独统计——**不要**把它们算进 micro-F1。

## 6. 决策树

```
误检太多？
├─ 单镜头视频被切碎
│   ├─ t_abs 是不是 0 或很小？        → 加绝对下限，重新标定
│   ├─ 局部统计用了 mean/std？        → 换 median/MAD
│   └─ 有闪光/甩镜？                  → 开持续性检验，调 persist_snr
├─ 每帧都在抖
│   ├─ bins 太多（如 64³）            → 降到 8³ 或 18×4×4
│   └─ 编码噪声大                     → 下采样到 320 宽 + 直方图平滑
└─ 切点前后各检出一个
    └─ local_max_gap 太小             → 提到 4~5

漏检太多？
├─ 两个镜头颜色分布相似               → 直方图无解，加 SSIM/ECR/分块直方图
├─ 切点很弱（淡入淡出、相似场景）     → 降 t_abs 并配合空间校验
├─ min_shot_len 太大                  → 降到 0.2~0.3s
└─ 阈值被切点自己抬高                 → 确认用的是 median/MAD
```

## 7. 阈值速查（HSV 18×4×4 + L1）

| 素材类型 | `t_abs` | `k_mad` | `min_shot_len_s` |
|---|---|---|---|
| 电影/剧集（切点清晰） | 0.38 | 6 | 0.5 |
| 短视频/快剪 | 0.35 | 6 | 0.2 |
| 访谈/口播（几乎无切） | 0.45 | 8 | 0.5 |
| 体育/手持跟拍（运动剧烈） | 0.45 | 8 | 0.3 |
| 监控/固定机位 | 0.30 | 5 | 1.0 |

换到 RGB 8×8×8 时，噪声底更高，`t_abs` 一般要 +0.05 ~ +0.1，**务必重新标定**。
